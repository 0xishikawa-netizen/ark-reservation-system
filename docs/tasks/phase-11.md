## 2. 目的

Excel / Googleスプレッドシートで手動運用している日計、月計、新規・顧客統計、スタッフ別・時間帯別稼働率、
勤怠・勤務時間、年間計画・実績、既存Excel帳票、過去データ取込をARKへ段階的に統合する。

最重要要件は**数値の正確性**である。予約 → 来店 → 施術 → 会計 → 決済 → 集計 → Excel出力を、
同一の事実データと共通の集計定義から一貫して算出する。月計表や日計表そのものを正データとして保存しない。
ただし、明細を復元できない過去の集計値は架空明細を作らず、出典付きの過去集計値として分離する。

## 3. Phase 11 共通原則

- 既存予約、顧客、決済、回数券、月額、権限、監査、外部連携を破壊しない。migrationは原則として追加・段階移行とし、既存カラムの意味を変えない。
- 金額は整数で扱い、丸め規則を1箇所へ集約する。浮動小数点で金額を計算しない。
- 集計画面ごとに独自SQLや独自定義を複製せず、共通のQuery / Serviceを利用する。
- 集計済みキャッシュを導入する場合も事実データを正本とし、再計算・突合手段を必須とする。
- 会計合計 = 会計明細合計 = 決済明細合計、税込 = 税抜 + 税額、スタッフ配分合計 = 元明細、配賦合計 = 元契約金額を保証する。
- 日次合計と月次日別合計、月次と年間月別合計は同じ定義から算出する。
- キャンセル、無断キャンセル、削除扱いのデータを完了来店や売上へ不適切に含めない。
- NULL / 未入力を0や「その他」に暗黙変換せず、統計上の「未入力」として追跡可能にする。
- 本番WordPress、本番DB、Stripe Live、Peak Manager実API、SALON BOARD実APIへ接続しない。
- Google Sheetsへの実書込、SALON BOARD連携、外部予約サイト同期、メール自動送信はPhase 11の対象外。

## 4. 確定済み業務定義

### 4.1 来店・ロング・メニュー分類

- **来店数**: 来店完了となった来店件数。同一来店で複数メニューを受けても1件。過去帳票の「施術数」は新規主要指標にしないが、過去値は削除しない。
- **ロング**: 1来店に含まれる施術時間の合計が `> 60分`。60分はfalse、61分はtrue、30+30分はfalse、30+45分はtrue、単一75分コースはtrue。1来店につき最大1で、複数スタッフ担当でも重複計上しない。
- **メニュー分類**: `M`（マッサージ）、`T`（トレーニング）、`A`（はり）、`M&T`、`A&T`。将来の分類追加を妨げない構造にする。

### 4.2 次回予約・初診・顧客推移

- **次回予約人数**: 来店・会計完了時点で、その顧客に未来の有効予約が存在したかを来店単位の0/1で保存する。完了後のWeb予約や後日のキャンセルで過去スナップショットを変えない。
- **初診**: その顧客の最初の完了来店。
- **初診予約**: 初診来店の完了時点で次回予約スナップショットがtrueの来店。
- **新規**: 過去に完了来店がなく、対象月に初めて完了来店した顧客。
- **離反**: 先々月に来店あり、かつ先月に来店なしの顧客。
- **再診**: 対象月に来店あり、先月に来店なし、先々月以前に来店履歴ありの顧客。新規は含めない。
- **継続率**: 初診顧客の2回目、6回目、10回目到達率を個別に算出する。手入力しない。分母0は0%へ暗黙変換せず、UI / export仕様で未算出として扱う。
- **Task 11-7で確定したcohort・観察日**: 対象月の新規顧客を分母とし、指定`as_of_date`までの完了Visitだけで2 / 6 / 10回目到達を判定する。最近月も分母から除外しない。再診と離反は排他的でない。
- **初診時年代**: 初診営業日時点の満年齢snapshotから、0〜9歳、10代、20代、30代、40代、50代、60代、70代、80代、90代以上へ分類する。年齢不明はunknownとして母数に残す。区分codeと表示は`AgeDecadeBucket`で一元管理する。

### 4.3 売上・税・決済

- **決済日基準売上**: 既存帳票互換。回数券・月額等は決済日に受領額を計上する。既存帳票の既定値とする。
- **施術日基準売上**: 経営分析用。回数券・月額等の契約金額を実際の利用へ配賦する。全利用への配賦合計は元契約金額と必ず一致し、端数は決定的な規則で調整する。
- **税**: 商品種別から税率をハードコードしない。メニュー / 商品は適用期間を持つ税区分へ関連し、会計明細には会計時点の税率、税抜額、税額、税込額をスナップショット保存する。
- **複数決済**: 1会計に複数の決済明細を許容する。例: 11,000円 = 現金5,000円 + PayPay6,000円。既存Stripe `payments`との責務・互換関係はTask 11-1で確定する。

### 4.4 スタッフ配分・稼働率

- 1来店 / 施術を複数スタッフが担当でき、担当時間を保持する。売上は原則として担当時間で按分し、端数調整後の配分合計を元売上と一致させる。
- 店舗全体の来店数、ロング、次回予約人数はスタッフ数分だけ重複計上しない。患者単位指標のスタッフ帰属は原則として主担当とする。
- **既存互換稼働率**: 稼働分数 ÷ 勤務時間。
- **予約可能時間稼働率**: 稼働分数 ÷ 実際に予約可能だった時間。休憩、会議、研修、予約不可ブロック等を分母から除外可能にする。
- 分母0は未算出として扱い、0%と混同しない。

### 4.5 時間帯・曜日

- 時間帯は最低限 `10:00–12:00`、`12:00–15:00`、`15:00–18:00`、`18:00–21:00`。
- 区間を跨ぐ施術・勤務・予約可能時間は境界で分割する。11:30–12:30は前半30分、後半30分。
- 既存帳票互換の平日は月〜金、土日は土・日。祝日も曜日どおりに扱う。

### 4.6 NULL / 未入力

- 性別、年代、目的、動機、住所その他のカルテ項目はNULLを許容し、未入力を統計母数から勝手に除外しない。
- 「その他」と「未入力」は別区分とする。
- 年代は初診日時点の生年月日からの自動算出を優先する。生年月日がない場合の手入力年代の採否と優先順位はTask 11-1で確定する。

### 過去データ
