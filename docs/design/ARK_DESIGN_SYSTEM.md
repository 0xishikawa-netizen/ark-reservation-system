# ARK Design System

Phase 9.6 で確定した ARK 予約・決済システムのデザイントークン正本。
色は `resources/js/plugins/vuetify.ts`（Vuetify テーマ）が実装上の正本、
本書はその **根拠（なぜこの色か）** を記録する。

---

## 1. Source（調査結果）

- **正本サイト**: <https://ark-conditioning.com/>（ARK Conditioning Laboratory 公式）
- **調査日**: 2026-09-10
- **調査方法**: 実サイトを読み込み、以下を機械抽出した。
  - 適用中の stylesheet 一覧
  - 子テーマ CSS（`twentytwenty-child/style/css/common.css` 他）の全 hex / rgb トークンを出現回数集計
  - 主要要素（`body` / `a` / `h1`–`h3` / `header` / `nav` / `.btn` / CTA / footer）の computed style
  - ロゴ画像 `wp-content/uploads/2023/04/ark_conditioning_logo.png` を canvas に描画してピクセルサンプリング
- **プラットフォーム**: WordPress（親テーマ `twentytwenty` + 子テーマ `twentytwenty-child`）
  - `--wp--preset--color--*`（例 `background:#f5efe0`, `accent:#cd2653`）は **twentytwenty の既定値**であり
    ARK の選定色ではない。子テーマ `common.css` が実際の ARK 配色で上書きしている。**preset 変数は採用しない。**

### CONFIRMED / INFERRED の区別

| 区分 | 意味 |
| --- | --- |
| **CONFIRMED** | 公式サイトの CSS もしくはロゴ画像から直接抽出した値 |
| **INFERRED** | CONFIRMED 値から業務アプリ向けに導出した値（対比・可読性・面の分離のため）。公式サイトには対応する値が存在しない |

## 3. Semantic colors（システム用・INFERRED）

公式サイトは marketing サイトのため success/warning/info の色を持たない（赤 `#c30d23` のみ）。
以下は **業務アプリ用に導出**した値。全て white 上でテキストコントラスト比 ≥ 4.5:1、
かつ brand navy と色相で明確に分離することを条件にした。

| token | 値 | 区分 | 根拠 / 使いどころ |
| --- | --- | --- | --- |
| `success` | `#1F7A4D` | INFERRED | 緑。予約確定 / 支払い成功 / 会員 active / 継続 |
| `warning` | `#A85F00` | INFERRED | 琥珀。猶予期間 / 要注意 / 一部返金 / キャンセル進行中（white 上で AA 4.5:1） |
| `error` | `#C0261C` | INFERRED（`#c30d23` を母色に微調整） | 赤。失敗 / 停止 / no-show / 取消不能な破壊操作 |
| `info` | `#0A6FA6` | INFERRED | azure。`brandAccent #0087C5` の暗いきょうだい（テキスト可読性確保）。中立の案内 / 3DS 待ち |

`#C30D23`（公式の生の赤）は「brand red の参照値」として保持。塗り面には彩度を少し落とした `error` を使う。

## 4. Typography

- **CONFIRMED**: 公式は `メイリオ, "ＭＳ Ｐゴシック", Meiryo, "MS PGothic", sans-serif`（日本語システムフォント、Web フォント非依存）。
- **本システム**: 既存の Hiragino 優先スタックを維持しつつ Meiryo を明示的に含める。
  意図（システム日本語フォント・オフライン可・高速）は公式と一致。
  ```
  "Hiragino Kaku Gothic ProN", "Hiragino Sans", "Noto Sans JP",
  "BIZ UDPGothic", Meiryo, "MS PGothic", system-ui, -apple-system,
  BlinkMacSystemFont, "Segoe UI", sans-serif
  ```
- 見出し: weight **700**、`letter-spacing: 0.01em`、`line-height: 1.4`
- 本文: `line-height: 1.7`、`letter-spacing: 0.01em`（日本語可読性）
- 本文サイズ基準 16px（公式は 18px だが業務アプリの情報密度に合わせ 16px 基準）

## 6. Status representation（ステータス色の分離）

`resources/js/design/tokens.ts` の `statusColor()` が業務状態 → Vuetify カラー名を一元マッピングする。
**brand navy（primary）は「進行中／受付」だけに使い、正常・警告・失敗は semantic 色を使う。**

| 意味 | 色 token | 対象ステータス例 |
| --- | --- | --- |
| 進行中・受付 | `primary`（navy） | `pending`, `pending_payment`, `processing`, `authorized` |
| 正常・継続 | `success` | `active`, `confirmed`, `completed`, `paid`, `succeeded` |
| 要注意・猶予 | `warning` | `grace`, `canceling`, `partially_refunded`, `refunded` |
| 失敗・停止 | `error` | `failed`, `paused`, `no_show`, `voided` |
| 終了・中立 | `grey` | `canceled`, `expired`, `exhausted` |

色だけに頼らずラベル（テキスト）を必ず併記する（§Accessibility）。

## 10. Navigation

| 面 | スタイル |
| --- | --- |
| Customer AppBar | `color=surface` / 下ボーダー / ブランド名 navy 太字 + ロゴマーク |
| Customer BottomNav | `color=primary`（選択タブ navy）/ アクティブインジケータ navy 3px |
| Admin NavigationDrawer | **navy レール**（`color=primary`）。ヘッダーに ARK ロゴマーク + 白のワードマーク。グループ見出しは `rgba(255,255,255,.82)` 太字・字間 0.14em、グループ間は余白 + `rgba(255,255,255,.09)` の細い罫で区切る。非選択項目のアイコンは opacity .65、選択項目は `rgba(255,255,255,.17)` 塗り + 白太字 + アイコン不透明 + **左 3px の明るい azure `#29A3DA` アクセントバー**（navy 上で視認しやすい logo azure の明るめ）。幅 256、作業領域は明るく保つ。折りたたみアイコンレールには**グループアイコン**に加えて、店舗の主要動線である **予約台帳 / 勤務枠** の直接ショートカット（tooltip つき）を常設する |

**メニュー構成**：`ブッキングボード`（ヘッダー先頭の単独タブ）→ `ダッシュボード` → `予約一覧` → …、`勤務枠` は `設定` グループに置く。台帳は日常のメイン画面なので必ずヘッダー経由で全画面から到達できるようにする。権限（`reservationsView` / `reservationsManage` / `shiftsManage`）による表示制御は維持。

**新規予約の入口はブッキングボードに一本化**：専用の新規予約画面（`/admin/reservations/create`・`Admin/Reservations/Create.vue`）は廃止した。予約作成は台帳のパネル（`panel=create`）から行う。予約一覧の作成ボタンも `/admin/schedule?panel=create` を指す。

**画面名の表記ルール**：予約台帳は UI 上では **「ブッキングボード」** と表示する（ヘッダーメニュー／ページタイトル／各画面からの導線ボタンすべて）。履歴一覧ではなくタイムラインの"ボード"であることを名前で示すため、Log ではなく Board を採用した。コード・ドキュメント内部の呼称は従来どおり「予約台帳 / schedule board」を使う。

**予約枠の粒度**：全面的に **5分単位**（`reservation.slot_minutes = 5`）。空き時間の候補・開始時刻のバリデーション・台帳のスナップがすべてこの値に従う。台帳は細かい粒度だとカーソルがどの時刻を指しているか分からないため、**カーソル位置ガイド**（accent の破線＋時刻ラベル、枠と同じ単位にスナップ）を常時表示する。現在時刻線（navy の実線）とは線種・色で区別する。

**新規のお客様（電話予約）**：未登録のお客様の予約は、新規予約パネルの「新規のお客様（電話予約など）」から **仮登録** して取る。電話口では氏名が聞き取れない・漢字が分からないことがあるため、**氏名・カナ・電話番号のうち分かったもの1つ以上**で作れる（すべて空は 422）。氏名が無い場合の表示名は カナ → `未確認（電話番号）` → `未確認のお客様` の順でフォールバックする。`created_via = 'admin'`、ログイン用パスワードは持たせず、メールは `@ark.invalid`（RFC 2606 の予約ドメイン）のダミー。会員番号は通常どおり発番され、来店時に顧客詳細から正しい情報へ上書きする運用。

**ログイン後の着地**：`reservations.view` を持つ店舗スタッフは、ログイン直後（`/`）に管理ダッシュボードではなく **ブッキングボード** へ着地する（`HomeController`）。ダッシュボード最上部にもボードへの navy の導線カードを常設する。
| Admin AppBar | `color=surface`（**白**。濃色バーにしない — 長時間運用の眩しさ・視線移動コスト回避）。左に小さいロゴマーク、右はユーザー名 + 縦罫 + `variant=tonal` のログアウト |

`aria-current="page"` を選択中項目に付与。navy レール上の白文字はコントラスト比 ≈ 13:1（AA 余裕）。

## 12. Admin UI

目標: **ARK ブランドを保ちつつ、毎日長時間使える業務システムの可読性・操作速度を優先**。

- **ブランドの居場所は周辺に置く**：navy は左レール（NavigationDrawer）とアクセント（見出しの罫、
  KPI タイルの上辺）に集中させ、**中央の作業領域は白基調**（`background #F5F6F8` + 白カード + 枠線）に保つ。
- 濃い navy の**トップバー**やヒーローは使わない（眩しさ・視線移動コスト）。
- ステータス・警告は semantic 色（navy で潰さない）。KPI タイルの上辺 3px アクセントは
  その指標の semantic 色（primary/warning/error）を使う。
- ページ見出し（`PageHeader` の h1）に navy の細い縦罫を付け、全管理画面で一貫したブランド感を出す。
  カード（`SectionCard`）のタイトルには付けない（画面内で反復すると煩雑なため）。
- 表・フィルタ・一覧の情報密度を優先（`density=compact` を許容）。
- Customer 画面と「同じ製品」に見えるブランド一貫性（ロゴ・色・タイポ）は保つが、レイアウトの密度は別物でよい。

### 12.1 予約台帳（Schedule board）

- 横型タイムライン。`pixelsPerMinute = 3.2`（30分予約でも顧客名・バッジが読める幅を確保）。
- **10分グリッド（3段階）**：1時間＝濃い / 30分＝中 / 10分＝ごく薄い。トラック背景に
  `repeating-linear-gradient` 1 枚で描画（DOM を増やさない・§19）。時間ヘッダーは1時間見出しを維持。
- **予約可否の帯**：稼働外（グレーのハッチ）／満席・予約不可（琥珀）／現在時刻（navy 線）。凡例つき
  （`axis='both'` では対象リソース種別が曖昧になるため満席帯を出さない。ARCHITECTURE §4.5）。
- **今日ボタン**：前日/今日/翌日の中央に配置し、`variant="flat" color="primary"`（他 2 つより視覚的に主）。
  表示中の日が本日なら `toolbar-today--current`（枠の強調）で現在地を示す。
- **軸切替**：スタッフ／ブース／**両方**。両方はスタッフ行のあとにブース行を続け、横幅いっぱいの
  「👥 スタッフ」「▣ ブース」見出し行を挟んで区切りを明確にする（レーンラベル列とトラック列は同じ
  `displayRows` を辿るため行数・高さは必ず一致する。§4.6）。
- 予約カードのクリック＝**台帳専用の左サイドパネル**（§12.2）を開く（画面遷移しない）。
- **予約カードのレイアウト**（メニュー色を左アクセント/淡色背景に使う。彩度の高い塗りは使わない）：
  1行目＝性別バッジ（「男」「女」の文字。色だけに頼らない）＋顧客名 ⋯ 状態アイコン（tooltip・aria-label
  付き）。2行目＝（新規客のみ）「新」バッジ＋開始〜終了時刻。3行目＝（指名ありのみ）「指名」バッジ（アイコン
  ＋文字・tooltip「指名予約」）＋メニュー名。**担当者名・支払い方法・予約経路・Stripe 情報はカードに出さない**
  （台帳の視認性を優先。詳細はパネルで確認）。「新規」判定は `ScheduleQuery` 側で、キャンセル・期限切れを
  除いた予約のうち最古が当該予約なら true。未登録の性別は推測せず非表示。
- **指名**（`reservations.is_staff_requested`）：新規予約・編集フォームでチェックボックスとして指定でき、
  カードには指名の場合のみバッジを表示する。詳細は ARCHITECTURE §4.6。
- **空きセルクリック**：時間軸の空いているセルをクリックすると「◯時から［予約を入れる］［予定を入れる］」の
  小さな選択が出る。「予約を入れる」で新規予約パネル、「予定を入れる」で予定ブロック作成パネルを開く
  （§12.2）。この導線があるため、台帳上部の「新規予約」ボタンは削除した（検索パネル内に小さな
  「新規予約を作成」導線のみ残す）。
- **スタッフ名クリック→勤務枠**：レーンラベルの担当者名をクリックすると `/admin/staff-shifts?staff_id=` に遷移し、
  対象スタッフが選択済みの状態で開く。この導線があるため、台帳上部の「勤務枠」ボタンは削除した。
- **ドラッグ&ドロップ**（§13-17, §27-32, §40）：未来の `confirmed` の予約、および予定ブロックがドラッグ可。
  **時間・担当スタッフ・ブース・日付**のいずれも変更できる（同一パネル内で完結・別行を増やさない）。
  10分スナップ・確認ダイアログ必須（変更前/後の日付・時刻・担当を提示）・サーバー再検証
  （`ReservationService::reschedule` / `ScheduleBlockService::update` 再利用）。日付変更は前日/今日/翌日
  ボタンへのドロップで検知する。ドラッグ中は元カードを半透明にし、顧客名・時刻を表示する追従ゴーストカードを
  表示する。ドロップ先レーンは azure（良さそう）/ red（重なりそう）の簡易ヒントを出すが、最終判定は必ず
  サーバー側。`axis='both'` では対象リソース種別が曖昧になるため D&D を無効化し、カードに
  「予約の移動は『スタッフ』または『ブース』表示で行えます」の tooltip とカーソル変更で理由を伝える。
- **クリック / ドラッグの分離**：ドラッグの「動いた」判定は水平移動・垂直移動（レーン変更）・日付ドロップの
  いずれかが真になった時点で確定する（`DRAG_THRESHOLD_PX = 6`）。ドラッグ直後の click は
  `suppressNextClick` で無視し、D&D 完了時にパネルが誤って開かないようにする。
- **予定ブロック**（休憩・ミーティング・事務作業・清掃・研修・外出・その他）：予約カードとは明確に区別し、
  破線の淡いニュートラル色（種類ごとに warning/info/success/accent/secondary を弱く配色）で表示する。
  メニュー色は使わない。詳細は ARCHITECTURE §4.6。
- **当日サマリー**：台帳（タイムライン）の**下**に「本日の集計」という横長カード1枚（予約/来店完了/新規/

  だけに集中させる。7 枚の大きな KPI カードにはしない。実 DB 集計のみで、推測・加工した指標は置かない。

  （× クリックのみ）。最大 5 件表示・超過は「ほか○件」。クリックでその日の台帳へ移動し対象カードをハイライト、
  ×で閉じた通知は管理者ごとに DB へ既読を記録し再表示しない（ARCHITECTURE §4.5）。

### 12.2 台帳サイドパネル（顧客詳細／顧客検索／新規予約／予定作成／予定詳細の共用パネル）

**設計思想**：Peak Manager の「台帳を見ながら左側だけで日常業務の大半を完結できる」という業務導線・
情報密度の考え方を参考にしつつ、見た目（配色・レイアウト・UI部品）は一切コピーしない。ARK 独自の
navy／azure／白・薄い境界線・メニュー色・控えめな semantic color で、狭いが見やすく、押す場所が
迷わないUIに仕上げる（2026-09-15 最終改善）。

- 予約台帳の**左**に差し込む（`[管理ナビ][台帳サイドパネル][台帳本体]`）。**台帳本体は押し出さず**、
  本体側が縮んで内部スクロールする（現在時刻・表示範囲を保つ）。閉じるボタン / ESC で閉じる。
- **幅は全モード共通で固定**：PC（≥1280px）は **312px**、1024〜1279px は 292px、1024px未満は全幅
  オーバーレイ。モードごとに幅を変えない（台帳側をこれ以上狭くしない・短時間メニューの予約カードの
  顧客名が読めなくならないことを優先するため）。
- **`PanelShell.vue`** が共通シェル（`PanelHeader.vue` によるヘッダー：左に必要な時だけ「← 戻る」＋
  種別アイコン＋タイトル、右に🔍検索／＋新規予約／×閉じる。本文スクロール領域。最大2ボタン程度の
  固定フッター）を提供し、6つのモードすべてがこれを土台にする（§8-9・ARCHITECTURE §4.6）。
  常設の顧客検索バー（`PanelCustomerSearchBar.vue`）は、どのモードでも本文の一番上に固定表示する。
- **文字サイズ密度**：メインタイトル 14px、セクション見出し 12px、通常テキスト 12〜13px、補助情報
  11〜12px 程度。階層は文字サイズだけでなく navy見出し・薄い背景・1px境界線・小さなバッジ・アイコン・
  ボタン色・余白でも作る。
- **ボタン色ルール（ARK全体で統一）**：primary（navy `flat`）＝そのモードで最も使う主要操作
  （予約する／保存／来店完了。**1画面に原則1つ**）。accent（azure `outlined`）＝遷移・補助操作
  （顧客詳細／予約編集／再予約／空き時間を確認）。error（`outlined`か、危険操作のみメニュー内で
  テキスト強調）＝キャンセル／無断キャンセル／削除（確認ダイアログ必須）。text（白 or グレー）＝
  戻る／閉じる／やめる。ベタ塗り（`flat`）は主要操作1つだけに使う。
  - **左パネル内部の「戻る」**：`Schedule/Index.vue` がモード遷移のたびに直前の状態（軽量な
    `PanelQueryOverrides` のスタック、深さ最大5件）を積み、`PanelHeader` の「← 戻る」で1件ずつ戻す。
    ブラウザ履歴は増やさない（既存の `router.get(..., replace: panelOpen.value)` は変更なし）。
    新規予約・予定追加・予定削除など一連の流れが完了した時はスタックを空にする。
  - 顧客検索は氏名・カナ・電話番号・会員番号で検索し、**閲覧操作なので `reservations.view` で使える**
    （旧 `reservations.manage` は更新操作専用に統一。§19）。「戻る」で検索へ戻った時、検索語・検索結果・
    ドロップダウンのスクロール位置は保持され、再検索は不要（`PanelCustomerSearchBar` は常時マウントの
    まま `v-show` でドロップダウンの開閉のみ切り替え、選択時も検索語・結果は消さない）。
  - **顧客詳細**（`ReservationDetailPanel.vue`）：予約カードクリック、または顧客検索の選択結果から開く。
    上部は氏名優先（カナ→氏名+**男/女**→会員番号+**顧客詳細ボタン**（Customer 360 へ）→TEL）。
    **利用状況**（来店回数／回数券残数／月額プランを太字の数字中心で1セクションにまとめる。巨大カードを
    並べない）。**顧客メモ**は独立セクション（`customers.note`。予約備考 `reservations.notes` とは別物。
    4行クランプ+もっと見る）。**今回の予約**は顧客情報と背景を分け、日時/メニュー/担当（**指名**バッジ）/
    ブース/状況を常時表示し、経路/支払方法/金額/備考/キャンセル理由だけ「さらに詳細を見る」で展開。
    フッターは状態に応じて最大2ボタン（例：予約前は [来店完了(primary)][予約編集(accent)]）＋
    使用頻度が低い/危険な操作（新規予約・決済確認・キャンセル・無断キャンセル）をまとめた「…」メニュー。
    **来店履歴**（新しい順・初期20件、行に**再予約**〈アイコン+テキスト、アイコン単独にしない〉。
    行クリックでその日の台帳へ移動＋対象カードへ自動スクロール＋一時ハイライト。超過は Customer 360 へ）。
    **メール・生年月日・住所・電話番号は表示しない**（Customer 360 に残す）。
  - **顧客検索**（`CustomerSearchPanel.vue`）：検索欄自体は常設バー側にあり、このモードは「まだ何も
    選んでいない」既定表示（ヒント文＋新規予約ボタン）。結果選択で顧客詳細モードへ。
  - **新規予約**（`NewReservationPanel.vue`）：空きセルクリック（「予約を入れる」を選んだ場合）／来店履歴の
    **再予約**から開く。上部に選択中の枠（日付・時刻・担当）を要約表示。メニュー選択は通常の `<select>`
    ではなく **`MenuPicker.vue`**（§12.4）。担当スタッフを選ぶと**指名**チェックボックスが出る。
    再予約は顧客・メニュー・担当を事前入力するだけで、**既存 DB 行を直接複製しない**（日付・時刻は必ず
    新規に選び直す）。送信は既存 `POST /admin/reservations` のみ（`Admin/Reservations/Create.vue` と
    業務ロジック共有）。
  - **予定を追加**（`ScheduleBlockCreatePanel.vue`）：空きセルクリックで「予定を入れる」を選んだ場合に開く。
    上部に選択中の枠を要約表示。種類はよく使う4種（休憩/ミーティング/事務/清掃）をチップで大きく、
    残り3種（研修/外出/その他。その他はタイトル必須）は補助チップで小さく。対象（スタッフ／ブース）・
    日付・開始/終了（10分単位）・メモを入力し `POST /admin/schedule/blocks`。
  - **予定詳細**（`ScheduleBlockDetailPanel.vue`）：台帳上の予定ブロッククリックで開く。種類・時間・対象・
    メモをシンプルに表示し、「編集」（accent outlined）でパネル内インライン編集フォーム（種類は同じ
    チップUI）に切り替え（`PUT /admin/schedule/blocks/{id}`）、「削除」（error outlined）は確認
    ダイアログを経て `DELETE /admin/schedule/blocks/{id}`。
- データは集約 API（`GET /admin/reservations/{reservation}/panel` または
  `GET /admin/customers/{customer}/board-panel`、いずれも `ReservationPanelQuery`）で 1 レスポンス。
  `can:reservations.view` で閲覧、顧客情報は `can:customers.view` を持つ場合のみ含める。
- 状態は URL（`/admin/schedule?...&reservation=` / `&customer=` / `&block=` / `&panel=`）が正本。
  カード/検索結果クリックで `router.get(..., preserveState/preserveScroll)`、戻る/進む/リロードで自然に開閉。
  左パネル内部の「戻る」はこの URL 駆動の仕組みの上に乗る軽量な追加機能であり、置き換えではない。
- 来店履歴の行クリック → その日の台帳へ移動し、対象カードへ自動スクロール＋数秒の一時ハイライト。
- Customer 360（`/admin/customers/{id}`）の置き換えではない。詳細編集・全決済・回数券/月額操作は Customer 360 に残す。

### 12.4 MenuPicker（自作メニュー選択UI）

- `components/admin/MenuPicker.vue`。新規予約パネルの「メニュー」行をクリックすると、台帳中央付近に
  コンパクトな `v-dialog`（最大幅420px）で開く。**左パネル自体をメニュー一覧で埋めない**——312px幅の
  制約を守ったまま、メニュー数が増えても対応できるようにするための独立コンポーネント。
- 表示項目はメニュー色（丸ドット）・メニュー名・所要時間・カテゴリ・料金のみ。説明文は表示しない
  （店舗スタッフ向けなので、選ぶための情報だけに絞る）。カテゴリチップ（すべて／カテゴリ別）と
  名前・カテゴリでの検索欄を持つ。**「よく使う」**（店舗全体・直近30日の`confirmed`/`completed`実績を
  `service_id`で集計・1クエリ。個人別の最適化はしない）を検索・カテゴリ未絞り込み時だけ上部にまとめて
  表示し、その下に「すべてのメニュー」を続ける（2026-09-15 実装。詳細は ARCHITECTURE §4.7）。
- メニューを1件クリックすると即選択され、ダイアログは閉じて新規予約パネルへ反映される。選択後は
  既存の `AvailabilityService` 呼び出し（`GET /admin/reservations/availability`）がそのまま走る——
  フロント側に空き時間判定の独自ロジックは追加していない。
- ESCで閉じる・フォーカストラップは Vuetify `v-dialog` 標準機能に依拠。
